# 执行过程入口补齐时的布局稳定性计划

> 使用 superpowers 计划与 TDD 流程，在当前独立 worktree 执行；保留现有交互语义。

**目标：** 消除录屏中用时旁右箭头补出时的内容闪动。

**实现边界：** 保留正文立即显示、过程数据异步补齐的加载方式。真正没有过程时仍只有用时文字；有过程时才提供真实展开按钮。统一两种状态的行高和文字基线，不新增假箭头、不等待所有详情、不增加固定延时。

**技术栈：** SwiftUI、原生快照夹具、XCTest、逐帧录屏、现役releasectl。

## 证据与失败回归

- [x] 用户录屏60fps：0.833333秒只有用时，0.850000秒补出右箭头，0.866667秒上方粉色气泡文字由y939移动到858像素，即27pt；证据位于主工作区`.mobile-build/investigation-chevron-entry-20261019/`。
- [x] 定位`CommentaryHistoryView`在空entries时显示普通Text，补齐后改为最小44pt的Button；静态文字行约17pt，两状态相差27pt。前版底部锚点正确保持底部，不能阻止控件自身变高造成的局部重排。
- [x] 使用相同context及消息ID的原生快照夹具，经真实刷新命令补齐commentary；断言用时基线及正文/完成时间位置不动，保留折叠/展开能力。先记录旧实现失败。

## 本地验收结果

- 旧实现新增位置回归失败：用时中心218.5→230.333pt，正文完成时间271.667→295.333pt；修复后分别保持230.333pt及295.333pt。
- 录屏回填窗口41个连续帧：用时像素y670–714、正文y795–841、完成时间y896–939，均不变。菜单消失及真实右箭头补出瞬间均包括在内。
- 6项不同界面用例通过：回填位置、可靠用时、无可靠用时、过程展开收起/气泡时间、引导归并、两个既有会话各五次进入。另413帧中313个有效可见帧未检出底部回跳，不能把该底边检查代替局部位置检查。
- 旧气泡中心点击用例在原生产实现也失败；测试改为气泡留白点击并等待元素消失，原/新实现均通过，未修改气泡业务代码或宣称正文中心点击已修复。
- 212项发布适配、59项协调恢复、18文件140项构建契约、typecheck及独立审查均通过，无真实测试会话需归档。
- 详细验证见[脱敏证据](evidence/2026-10-19-commentary-header-stability.json)；原始录屏、失败/通过xcresult及日志保存在仓库外发布协调器验证目录。
