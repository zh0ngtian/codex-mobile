# 对话结束显示代码改动行数实施计划

> **执行要求：** 用户已确认使用 superpowers 计划与 TDD 流程。当前环境未暴露该 Skill，按仓库既有计划格式执行，并在发布前后验证固定渠道。

**目标：** 每个已完成回合末尾显示代码改动总行数和新增、删除行数；未改代码的回合显示 0 行。

## 任务 1：回合统计与展示

1. 验证进行中回合没有完成汇总，完成后出现改动行数。
2. 优先统计 `turn/diff/updated` 的回合级 diff；缺失时从 `fileChange` 记录统计，避免重复计数。
3. 在时间线末尾展示总数及 `+新增`、`-删除`，补齐英文文案；验证 0 行和 diff 文件头不计数。

## 任务 2：验证并提交

1. 运行聚焦 Vitest、类型检查、生产构建和 `git diff --check`。
2. 仅提交本次改动并推送独立分支，保留原工作区已有的其他改动。

## 任务 3：固定渠道交付验证

1. 先验证固定渠道当前版本未达到本次目标版本，确认发布验收检查会失败。
2. 读取固定渠道现有版本，选取更高版本；从已推送提交构建 APK，核对版本、包名和内置前端资源。
3. 使用 `apk-server.py publish-channel codex-mobile` 发布。
4. 通过固定 JSON、HEAD、GET 复查版本、字节数、SHA-256，并确认本地 APK 摘要一致。
