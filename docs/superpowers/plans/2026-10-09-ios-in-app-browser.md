# iOS 内置浏览器补齐计划

> **执行要求：** 按 superpowers 的 planning、TDD、verification-before-completion 流程逐项执行。

**目标：** 补齐 iOS 平台的独立内置浏览器，使普通 HTTP/HTTPS 链接与 Android 一样，不替换 Codex Mobile 主页面；同时提供关闭、动态标题、外部浏览器、重新加载、桌面版网页和全屏能力。

**交互边界：**

- 仅拦截用户主动点击或新窗口打开的普通 HTTP/HTTPS 链接；主页面和前端路由继续留在原 `WKWebView`。
- 文件下载与电话、短信、邮件等系统 Scheme 继续使用既有处理路径。
- 外部网页使用独立 `WKWebViewConfiguration`，不注册 Codex Mobile 的脚本桥接能力。
- 浏览器内的普通导航留在同一页面；标题优先使用网页标题，空标题回退到域名。
- 全屏时隐藏导航栏，并保留可恢复菜单；关闭后回到原会话状态。

## 任务 1：先写失败的平台一致性契约测试

1. 断言 iOS 构建流程会复制独立浏览器源文件。
2. 断言主 `WKWebView` 对普通 HTTP/HTTPS 点击和新窗口请求进行拦截。
3. 断言 iOS 浏览器具备动态标题、关闭、外部浏览器、刷新、桌面模式和全屏操作。
4. 断言外部网页容器没有注册应用脚本桥。
5. 运行聚焦测试，确认在实现前按预期失败。

## 任务 2：实现 iOS 独立浏览器

1. 新增 UIKit 原生浏览器控制器，使用独立 `WKWebView` 与系统符号构建导航栏和菜单。
2. 在 iOS 主 WebView 导航代理中接管普通网页链接，保留下载和特殊 Scheme 逻辑。
3. 支持同页导航、页面标题与加载进度、外部打开、刷新、移动/桌面模式切换和全屏恢复。
4. 把源文件复制步骤纳入 GitHub Actions 与本地 `ios:prepare` 的同一固定流水线。
5. 运行聚焦测试，确认契约转绿。

## 任务 3：构建与交互验证

1. 生成本地 iOS 工程并通过模拟器构建。
2. 若已有启动的模拟器，安装并验证链接打开、标题、菜单、刷新、桌面模式、全屏恢复和关闭返回。
3. 运行完整单元测试、类型检查、生产构建和差异检查。

## 任务 4：提交、推送与双平台固定渠道发布

1. 按仓库提交规范提交并推送本次计划、测试、原生实现与流水线修改。
2. 读取 Android、iOS 固定渠道版本，选择同时高于两者的统一版本。
3. 构建同版本 APK 和 IPA，并分别核对包版本、文件大小、SHA-256 与 IPA 签名状态。
4. 发布到固定 Android、iOS 渠道，通过两个清单以及 APK/IPA 的 HEAD、完整 GET 复核交付物。
5. 删除本次产生且不再需要的临时文件。
