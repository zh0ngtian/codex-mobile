# 推理强度冷启动竞态修复计划

**目标：** 修复冷启动后会话列表先于模型目录出现时，立即打开会话会把服务端推理强度错误显示为“智能”的问题。

**根因：** `loadThreadDetail` 的异步回调使用当前 React render 捕获的 `models`。模型目录尚未返回时，会话恢复得到的 `reasoningEffort` 会在缺少模型元数据的情况下被归一化为 `null`；模型目录随后加载完成，但不会重新恢复已经丢失的原始强度。

## TDD 步骤

1. 在 Playwright 中模拟 `thread/list` 立即返回、`model/list` 延迟返回。
2. 在模型目录返回前打开已有会话；`thread/resume` 返回 `gpt-6.1-sol` 与 `high`。
3. 先确认当前实现最终错误显示“智能”。
4. 调整会话设置恢复：目录未就绪时保留服务端原始推理强度，并使用最新模型目录引用做归一化。
5. 模型目录到达时重新校验当前选择，保证模型、推理强度和速度最终一致。
6. 跑定向 E2E、完整测试、类型检查与构建。
7. 提交并推送，构建高于固定渠道版本的 APK；真机执行冷启动快速打开场景，随后发布固定渠道并核对版本、大小和 SHA-256。
