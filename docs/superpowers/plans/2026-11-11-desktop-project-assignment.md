# 桌面会话项目归属修复计划

> 使用 superpowers:test-driven-development 以先失败再通过的回归验证改动。

**目标**：原生 App 的列表和会话页头显示桌面明确指定的项目。

**架构**：网关的项目目录接口提供本机桌面的项目根目录和会话归属。客户端用同一规则装饰会话和筛选分页，执行目录继续由上游会话的 `cwd` 提供。

**技术栈**：TypeScript、Vitest、App Server RPC、现有原生快照桥接。

**依据**：`docs/interaction-alignment.md` 第 4.2 节以及真实会话的桌面归属、项目根目录和 RPC 结果。开发基线为 `13679104e2a468443ee226ab9906c0dda5259565`。

## 约束

- 显式项目归属只影响展示和列表分页。每页继续按原活动时间取五条。
- 网关兼容旧目录响应。项目归属数据按设备隔离。
- 本次交付源码及验证结果。客户端发布和生产网关部署分别按仓库授权流程执行。

## 验证步骤

- [x] 用重叠的项目根目录复现分页错误，核对目标会话在原生页头的项目名和真实执行目录。
- [x] 扩展 `server/codex-projects.ts` 和 `src/backends/probe.ts` 的目录契约，验证显式归属、迁移身份、无项目及跨主机输入。
- [x] 在 `src/app-server/thread-list-loader.ts` 和 `src/App.tsx` 应用归属，统一普通列表、搜索、置顶及详情，并核对过滤后继续补齐分页。
- [x] 执行相关回归、类型检查和前后端构建，更新交互约定中的验收状态。
