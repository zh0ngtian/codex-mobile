# 首轮生成会话标题实施计划

> **执行要求：** 当前环境未暴露 superpowers Skill；按仓库既有 superpowers 计划格式执行，并遵循 TDD、系统化调试和完成前验证流程。用户已于 2026-10-02 确认开始。

**目标：** 新会话先显示“新对话”，首条用户消息携带一次性标题生成请求；从模型首条流式回复的隐藏标记中提取不超过 40 个字符且语言跟随用户的标题，持久化到 App Server 并立即刷新界面。后续回复不得自动改名，手动重命名保持可用。

**交互边界：** 标题请求和隐藏标记只参与模型上下文与传输，不得出现在用户消息、助手回复、复制内容或历史编辑内容中。标题生成、解析或持久化失败不影响原任务执行；一个新线程只接受首个有效标题。

## 任务 1：先写失败的标题协议测试

**文件：**

- 新增 `tests/ui/conversation-title.test.ts`
- 修改 `tests/ui/history-edit.test.ts`

1. 覆盖首条消息追加标题请求，后续消息保持原文。
2. 覆盖完整隐藏标记提取、可见文本清理、占位值/换行/超长标题拒绝和 Unicode 字符计数。
3. 覆盖未闭合流式标记不被提前提取。
4. 覆盖历史用户消息隐藏标题请求，编辑重发时不携带内部 Prompt。
5. 先运行聚焦测试，确认测试因能力缺失而失败。

## 任务 2：实现纯函数协议与展示清理

**文件：**

- 新增 `src/app-server/conversation-title.ts`
- 修改 `src/app-server/history-edit.ts`
- 修改 `src/features/conversation/Timeline.tsx`

1. 集中定义标题请求、隐藏标记正则和 40 字符规则。
2. 只为新线程首轮构造带标题请求的模型输入，乐观 UI 继续保留原始用户输入。
3. 对流式助手文本只在完整标记出现后提取，并从所有用户可见路径移除标记。
4. 对持久化历史中的首条用户消息移除内部标题请求，保证显示、复制和编辑均不泄露。

## 任务 3：实现一次性标题状态与持久化

**文件：**

- 修改 `src/App.tsx`
- 修改对应 UI/E2E 测试

1. 新线程创建后记录首轮标题生成资格和首个真实 `turnId`。
2. 监听首个助手消息的流式增量，以原始缓冲区等待完整隐藏标记。
3. 首个有效标题立即消费资格并调用 `thread/name/set`；同步线程列表、当前会话和搜索结果。
4. 首轮完成后关闭资格；后续消息中的同类标记只做隐藏清理，不能覆盖标题。
5. 标题请求、解析和写入失败不得中断或改变主任务状态；用户后续手动重命名继续覆盖自动标题。
