# 会话中部右滑呼出侧栏实施与交付计划

> **执行要求：** 当前环境未暴露 superpowers Skill；用户已确认按仓库现有 superpowers 计划格式和 TDD 流程执行。

**目标：** 在会话页面中部向右滑动时打开侧栏，同时保留左边缘入口，并避免与输入、弹层、纵向滚动和横向滚动内容冲突。

**现状证据：** 原有 `ConfiguredApp` 的全局触摸监听只记录 `clientX <= 24` 的起点，因此从屏幕中部开始的右滑不会打开侧栏。

## 任务 1：先写失败的手势测试

1. 增加会话中部右滑测试，断言超过位移阈值时只打开一次。
2. 覆盖左边缘、纵向滚动、多指触控、输入区、弹层和横向滚动区域。
3. 先运行聚焦测试确认失败，再实现手势逻辑；随后运行聚焦测试、完整测试和构建。

## 任务 2：实现并集成手势

1. 将侧栏手势识别抽成独立 Hook，限定在可见会话工作区。
2. 保留现有水平位移阈值，增加纵向偏移、多指和反向移动取消条件。
3. 在顶层应用调用 Hook，保留原有侧栏历史记录及返回键处理。

## 任务 3：提交与固定渠道交付

1. 检查暂存内容和提交规范，提交并推送本次改动。
2. 读取固定渠道当前版本；将移动端版本基线调整到至少该版本，使自动构建版本更高。
3. 推送主分支后下载该提交对应工作流构建的 APK；核对构建版本、嵌入资源和摘要。
4. 使用 `apk-server.py publish-channel codex-mobile` 发布，通过固定 JSON、HEAD、GET 核对版本、文件大小和 SHA-256。
5. 清理本次不再需要的临时文件。

## 补充任务：侧栏跟随手指拖动

**问题证据：** 首版在右滑超过 56px 时直接调用 `openSidebar`，拖动期间面板与遮罩没有随手指变化。

1. 先修改手势和 CSS 测试，断言拖动距离同步写入面板位移和遮罩进度、松手后再决定展开或收回，并确认旧实现失败。
2. 为侧栏层增加拖动状态；在确认横向手势后逐帧更新位移与遮罩透明度，松手时按距离或速度决定展开，取消时恢复关闭状态。
3. 验证纵向滚动、横向内容、多指触控和弹层不会误触发；运行聚焦测试、完整测试、类型检查和构建。
4. 按提交规范提交并推送，构建高于固定渠道 `0.2.57` 的 APK，发布后通过固定 JSON、HEAD 和 GET 回验摘要与大小。

## 补充任务：侧栏向左跟手收回

**问题证据：** 跟手手势只在侧栏关闭时接受会话工作区触摸；打开后忽略触摸，因此无法从侧栏向左拖动收回。

1. 先增加左滑跟手、松手关闭、短拖恢复及侧栏内部滚动边界测试，确认旧实现失败。
2. 根据侧栏开关状态选择会话工作区或侧栏面板为手势起点；复用水平位移、速度和取消判定，向左拖动时同步更新面板位置与遮罩透明度。
3. 运行聚焦测试、完整测试、类型检查和构建；检查本次暂存内容，提交并推送。
4. 将版本基线对齐固定渠道 `0.2.59`，构建更高版本 APK；发布后通过固定 JSON、HEAD、GET 核对大小与 SHA-256。

## 补充任务：从侧栏右侧遮罩左滑收回

**问题证据：** 左滑起点仅接受侧栏面板内的元素，右侧未被面板覆盖的遮罩区域无法开始拖动。

1. 先增加遮罩区域左滑跟手测试，确认原实现无法启动拖动。
2. 将侧栏打开时的起手区域扩展为侧栏覆盖层，沿用现有的位移、速度、滚动排除与松手判定；轻点遮罩仍由原有按钮关闭。
3. 运行聚焦测试、完整测试、类型检查和构建；检查暂存内容并提交推送。
4. 将版本基线对齐固定渠道 `0.2.60`，构建更高版本 APK，发布后通过固定 JSON、HEAD、GET 校验大小与 SHA-256。
