# Windows 后台启动优化实施计划

> 执行方式：使用 superpowers:executing-plans 在当前会话执行，按 TDD 验证并做最终独立审查。

**目标：** Codex Mobile 后台只保留计划任务入口，未变化的二进制不在每次登录时反复完整读取。

**架构：** 安装和更新时只移除目标属于本服务的旧启动快捷方式。SHA-256 结果保存在已有用户私有服务目录，以真实路径、文件身份、大小、纳秒修改/变更时间失效；缓存损坏则重新计算，读取过程中变化则拒绝使用。新复制快照仍需完整校验。

**技术：** PowerShell 5.1、Node.js 原生测试、现有计划任务与 GUI 启动器。

**需求来源：** 用户要求解决重复后台入口和约 495 MB 文件的多轮启动校验。

## 约束与审查重点

- 不停止承载当前会话的后台进程；部署下次启动会使用的脚本，并独立实测启动校验路径。
- 不修改客户端、网关构建产物、用户凭据或其他软件启动项。
- 文件同大小改写并恢复 mtime、可选文件新增/消失、缓存无效、快照损坏、路径带空格都必须被覆盖。
- 缓存是私有目录内的性能索引，不替代操作系统 ACL 或可信签名验证；缓存被同一用户恶意修改不属于新增安全边界。
- 当前部署源码在 feat/windows-independent-service 分支，基于该版本创建独立 worktree；提交推送本修复分支，避免混入其他客户端变更。
