已有决定：一个网关绑定一个账号/工作区，所有手机共享网关自己的 controller；Mac 负责授权、配对和恢复；不自动重新登记、不迁移账号或目标，不改变手机填写的 URL 或共用 token。

## 已确认 44：Mac CLI 只管理已运行的网关

CLI 通过当前用户专用的本机私有控制通道，调用已经运行的网关；状态、目录、首次授权、配对和恢复均由该网关实例执行。CLI 本身不创建官方 Remote 主连接，也不直接修改运行实例持有的绑定。

- 控制通道与手机网关 HTTP/WS 入口分开；只有当前 Mac 用户可以访问，手机 token 不能调用授权管理。
- 继续使用网关当前配置的 canonical app-server，不猜测其他端口、目录或运行实例。
- 网关未运行或私有通道无法证明归属时，明确提示先启动或修复指定网关；不自动另起 controller，不执行离线写入，不操作 launchd。
- 多个 CLI 命令仍由同一网关串行管理身份变更；普通只读状态可并行。启动竞争和进程退出必须有界、可核验，不按锁的年龄抢占活进程。
- 未授权状态下，本地模式仍可用；首次注册完成后，网关实例再启动唯一 Remote 主连接。

本项明确 CLI 在网关未运行时不能离线配置，进程归属和启动顺序必须保持唯一主连接。

## 已确认 45：撤销后的新身份先验证再切换

原登记撤销且无法继续使用原身份时，Mac 显式发起新授权；先在独立私有记录中完成网关自有新身份登记和本机配对/双ID证明，成功后原子切换活动身份。旧身份记录保留，失败不覆盖旧绑定。

- 新授权仍必须属于原完整受管身份（账号/工作区、用户和 canonical codexHome）；任一变化均拒绝原地覆盖，不将原队列迁入新的身份范围。
- 新身份准备期间停止旧身份的主连接；准备阶段只使用授权、canonical 管理与 REST，不并行建立第二条官方主连接。
- 新 controller 的逐台配对权限重新核验，不能继承或猜测旧 controller 的 grant；其他机器按需重新配对。
- 原队列继续暂停。原完整受管身份及目标 environmentId+installationId 均核验一致后，才允许 Mac 显式恢复；任何身份变化、未知发送结果或待确认项继续保持原有阻断。
- 目标重装时显式重新关联用于确认后续访问的新目标，旧操作不自动改写目标身份。
- 切换记录有原子提交点；进程中断后只采用已提交的活动身份，不凭最新文件时间猜测，不删除原队列。

本项明确不可复用的登记不能原地覆盖，必须保留旧身份并分阶段切换，再接入 CLI。
