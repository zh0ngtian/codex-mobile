# Sidechat 临时分叉聊天设计

2026-10-19 用户已批准本文对应的完整方案：独立全屏、多分支、空闲 24 小时过期，先在 iPhone 17 Pro 模拟器验收，不发布。

## 行为

主聊天更多菜单提供 Sidechat 入口，可新建或切换多个临时分支。创建时读取最近一个已结束回合，通过同一设备连接的 `thread/fork`，传 `lastTurnId`、`ephemeral: true`、`excludeTurns: true`。没有已结束回合时明确提示，不能退回复制整个聊天。继承原模型设置、机器、目录、容器；不启动第二个执行环境。

分支只显示分叉后新增消息。顶部返回主聊天保留分支，显式关闭先以系统小弹窗二次确认；取消保留分支、执行状态、待发内容与草稿，确认后停止当前执行、清除待发内容、取消订阅并移除本地关联。等待确认时会话或连接发生切换则拒绝旧关闭意图。每个分支独立运行，主聊天和其他分支仍可并行。空闲 24 小时清理，运行中不计时；从执行结束重新计时。daemon 重启后不保证恢复，失效时提示重新创建，不能偷偷创建替代分支。

注入专门 developer instructions：继承历史仅供参考；只执行本 Sidechat 新提出的请求；默认只读探索，修改必须由用户在此明确提出；不得创建子代理。分叉配置关闭 multi_agent。页面持续显示“文件目录与主聊天共享，获准修改会影响同一目录”。不把提示称为文件隔离或独立容器。

## 已批准的恢复补充（方案 A）

真实 App Server 0.144.1 的 ephemeral 分叉不支持 `thread/resume`、`thread/turns/list` 或 `thread/read includeTurns`。用户选择方案 A：新增专用网关内存会话，持续持有上游订阅和新增消息投影，手机更换连接或重启后通过 `mobile/sidechat/rpc` 的 read 操作恢复；daemon 重启后明确失效。Sidechat 专用通道绕开 HTTP 操作 WAL、内联图片落盘、回合文件变更历史落盘；普通聊天的持久化行为保持原样。先使用临时测试网关验证，不部署生产网关。

## 结构与数据

`src/sidechat/sessions.ts` 负责关联记录、内存投影、创建、回合事件、发送及内存队列、关闭和过期。持久记录白名单只允许设备/主聊天/分支/分叉回合/新增回合 ID 和时间；不存正文、附件、指令或执行结果。消息真实来源是 Codex，内存投影只用于界面显示。

BackendWorkspace 复用现有输入、审批和原生桥。Sidechat 事件先交给专用管理器，普通会话流程不再处理这些事件。进入/离开分支递增上下文代数，迟到命令不能跨聊天；普通聊天读取和恢复仍走原路径。原生桥只增加展示数据和有上下文检查的 Sidechat 命令。SwiftUI 使用现有 ConversationScreen 与 ComposerBar，网页和 Android 使用同一业务语义。

## 错误和验证

不支持 fork 参数、分叉点消失、daemon 重启或关闭失败均显示真实错误，不回退到普通聊天或完整历史复制。覆盖最新结束回合选择、隐藏继承历史、并行事件、队列、关闭、24 小时到期及持久白名单；验证原生和网页入口、返回、切换、共享目录提示及真实消息往返。测试聊天完成后归档，临时分支关闭。

本轮仅提交推送开发分支，构建安装模拟器，等待用户验收；不推进 main，不创建 Release，不更改固定渠道或已部署网关。
