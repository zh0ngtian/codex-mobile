# iOS 仅文字编辑区原生

用户已确认：“只有文字编辑区原生，附件、发送及所有选择按钮和菜单都改为网页”。本轮沿用仅 iOS 签名 IPA 与 OTA、不创建 GitHub Release 的交付授权。

## 呈现与职责

- 在已有网页界面 + 原生输入开关开启时，保留网页输入栏表单、附件入口和列表、发送/停止/排队、模型/推理/Fast/访问权限按钮及网页菜单；只有文字编辑区域使用原生控件。
- 复用网页 textarea 的布局位置作为编辑器锚点，原生编辑器只覆盖这个区域，不能挡住网页控件。网页继续拥有自然增缩和最大高度的布局预算，原生文字区内部可滚动；原生模式不显示最大化按钮。
- 保留同一业务 WKWebView 与 NativeRuntime，延用现有草稿版本、UTF-16 光标、上下文身份以及原生输入切换。原生编辑输出仍回到既有草稿处理，网页操作继续走原网页回调，不新增发送链路。
- 原生编辑器绑定当前可见 context。网页遮罩、侧栏、历史编辑、禁编辑、前后台或切换会话时，编辑器显隐、可编辑状态、焦点与生命周期都必须同步；旧几何/输入/焦点回调不能覆盖新会话。
- 全原生界面是现有独立选项，本次只修改网页界面中的原生输入模式；不删除完整原生界面的现有组件。

## 验收与交付

自动化先验证原生模式仍有网页控件和网页菜单、草稿及光标同步、阻挡/上下文门禁与原生开关关闭后的网页 textarea。真实界面仅在 iPhone 17 Pro、正常字号、竖屏验证：原生文字输入，网页模型/推理/Fast/权限选择及恢复输入、网页附件菜单/文件选择器取消、发送/停止的既有链路、长文本自然增缩与上限、会话切换和开关恢复。

先本地必要测试与独立规格/质量审查，提交推送固定 SHA；现役 `ios-composer-web-controls-20261017` 任务交给 `codex-mobile-ios-ota-production` 协调器冻结、构建、签名和发布，成功 receipt 后独立核对固定 IPA 与 HTTPS OTA。
