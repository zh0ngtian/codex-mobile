# Windows Codex 界面与共享服务分离设计（用户已确认）

## 目标

用户关闭并重新打开电脑上的 Codex 后，手机仍能连接同一个 app-server。后台自动监测 Codex 更新：配套二进制与运行中的 app-server 不一致时，等待所有任务空闲后自动同步并重启。保留手动重启入口。桌面和手机继续共享原有账号、会话和项目。

## 已确认的现状

- 现有 `start-shared-session.ps1` 将桌面界面、app-server、网关和 SSH 隧道放在同一个 Windows Job 中；界面退出后整个 Job 被清理。
- 现有计划任务 `CodexMobile-SharedDesktop` 在用户登录或专用快捷方式调用时启动；普通桌面入口不启动共享服务。
- 当前共享端口为 app-server 18765、网关 18766、服务器反向隧道 18767；维持这些端口及现有手机连接地址。
- 当前安装的桌面代码支持 `CODEX_APP_SERVER_WS_URL`；没有设置时，普通入口使用自己的默认启动方式。
- 当前安装包内 `codex.exe` 与桌面实际使用的用户目录副本 SHA-256 一致，版本均为 `0.162.0-alpha.17.2`。每次启动或重启动态查询当前安装包，避免固定 WindowsApps 的旧版本路径或按文件时间猜测版本。
- 手机访问口令已有 DPAPI 文件；SSH 私钥和服务配置均在仓库外。

官方 App Server 支持独立 WebSocket 监听及 `/readyz`、`/healthz` 健康检查，参见 [OpenAI 官方文档](https://learn.chatgpt.com/docs/app-server)。桌面环境变量的支持来自当前安装版本的本地检查，更新后仍需验证。

## 方案选择

推荐使用当前用户的独立后台计划任务。它能复用现有 DPAPI、Codex 登录及 SSH 权限，不需要管理员权限，适合这台电脑已有的运行方式。

另一种方案是安装 Windows 系统服务，但它需要管理员权限和独立账号/凭据处理。第三种方案是保留终端长期运行，部署更简单，但用户关闭终端会停止手机连接。因此本次采用当前用户后台任务。

## 服务生命周期

- 新后台任务仅维护 app-server、手机网关及 SSH 隧道，不创建或监控 Codex 界面进程。
- 同一后台任务维护透明的本机 WebSocket 入口，桌面和手机网关都经过该入口连接私有 app-server，以便切换期间暂停接单。对外仍使用原本机 18765 入口；真实 app-server 改用专用回环端口，部署前检查端口冲突。
- Windows Job 继续清理后台任务自己创建的子进程；界面不属于这个 Job。
- 用户登录时启动服务；关闭、重新打开 Codex 界面不停止服务。
- app-server 和网关仅监听本机回环地址；沿用现有带口令的公网网关与 SSH 隧道。
- 保留单实例互斥与端口检查，不接管或终止不属于本服务的进程。
- 首次部署必须识别当前普通界面已有的 app-server。不能直接再启动另一个写入同一会话的实例；准备与测试完成后，再安排一次退出旧界面、启动独立服务和重新打开界面的切换。

## 界面连接

- 界面通过 `ws://127.0.0.1:18765` 连接共享 app-server，不持有手机网关口令。
- 设置当前用户的桌面连接环境变量，并提供专用界面启动入口，在每次打开时显式设置连接地址，避免父进程保留旧环境。
- uTools 等已经运行的启动器需要重新加载用户环境；专用快捷方式不依赖这个步骤。
- 登录启动项只负责后台服务；界面由用户按需打开。
- 不修改 Codex 安装包或强制设置绕过 WebSocket 的 CLI 模式。

## 更新与重启入口

提供桌面上的“启动 Codex 界面”“重启 Codex 服务”“Codex 服务状态”入口。后台管理命令支持启动、停止、状态和重启。自动监测默认开启，手动重启作为备用入口。

### 自动对齐规则

- 每 60 秒检查当前已安装 Codex 所配套的 app-server，与本服务启动时记录的二进制摘要及版本比较。版本名称相同但内容不同也需要对齐；不会独立安装其他渠道的“最新版 CLI”。
- 只在版本不一致时进入待更新状态；版本一致时不重启。记录待更新原因、当前版本与目标版本。
- 通过 `thread/loaded/list` 完整分页枚举共享 app-server 的所有已加载会话，使用 `thread/read` 的运行状态判断；不使用手机列表过滤后的会话，不遗漏子 Agent。
- `active`，包括 `waitingOnApproval`、`waitingOnUserInput`，均视为忙碌。还需检查正在运行的后台终端、已接收尚未完成的请求及待处理操作；任何未知状态、查询失败或不支持的查询都不视为空闲。
- 持续空闲 30 秒后才尝试切换；其间出现活动则清除空闲计时并继续等待，不自动中断任务。
- 切换前关闭共享入口的新请求准入，等待此前已接收的请求完成，再完整复查会话、后台终端及待处理操作。如果再次出现活动，取消切换并恢复准入。
- 桌面与手机必须都经过可暂停准入的共享入口；不能只停止手机网关而让桌面仍能直接向 app-server 发起任务。没有这个屏障时禁止启用自动重启。
- 目标二进制在切换前重新解析并固定为经过校验的本机副本，避免安装更新与复制并发导致混合版本；保留上一可用的二进制和配套文件用于回退。
- 无任务后自动执行以下重启步骤。新服务健康和只读 RPC 验证成功后恢复连接；失败尝试恢复上一可用版本，记录失败并延迟重试，不陷入循环重启。

官方协议提供已加载会话、运行状态、状态变化通知及后台终端查询，参见 [OpenAI 官方文档](https://learn.chatgpt.com/docs/app-server)。查询状态与停止进程并非同一原子操作，因此准入屏障与切换前复查是本方案的必要部分，不能用两次轮询代替。

自动空闲切换或用户执行“重启 Codex 服务”时：

1. 检查当前服务身份及运行状态，识别正在运行的任务；有活动任务时拒绝默认重启。自动监测永远不强制中断任务，手动显式强制操作才允许中断。
2. 动态查询当前已安装 Codex 包，验证二进制存在并记录版本。
3. 停止本服务拥有的后台进程，等待旧端口释放。
4. 用新版二进制启动 app-server，等待 `/readyz` 成功，然后恢复网关与 SSH 隧道。
5. 使用现有访问口令核对本机与公网网关以及 JSON-RPC 初始化；失败明确报告，不标记为更新成功。

重启后台不会主动关闭 Codex 界面。需要实测当前桌面的断线重连；如果当前版本无法自动恢复，则报告需要重新打开界面。服务地址和手机口令保持稳定。

状态输出包含 app-server 版本、目标版本、是否等待空闲、二进制路径、PID、服务健康及网关健康；不包含访问口令、认证材料或会话正文。

## 验证与回退

- 先用测试创建的进程验证：关闭界面不停止后台；关闭后台只清理自身子孙进程；重复启动不双开。
- 用两个不同版本的测试二进制验证重启重新解析路径，不缓存旧版本。
- 验证自动监测：一致时不重启、不一致但有活动时等待、连续空闲才切换、审批/输入/子 Agent/后台终端均阻止重启。
- 验证检查后新请求到达的竞争：准入关闭前收到的请求被完整计入；关闭后不再进入旧服务；复查发现活动则取消切换。
- 验证查询失败、分页漏读、未知状态、安装更新中途变更、启动失败回退及同一目标失败后的退避。
- 验证更新解析或新服务启动失败、端口被其他程序占用、活动任务时拒绝重启，以及敏感信息不进入输出。
- 运行现有 Windows Job、External 网关和连接恢复测试；再做真实服务健康与 JSON-RPC 只读验证。
- 真实桌面退出、重新打开及后台重启需要一次用户配合的切换；当前会话和其他进行中的任务不能由本实现擅自终止。
- 注册任务和修改启动项前备份原任务、快捷方式及相关用户环境设置；回退可停新任务并恢复原共享启动方式。

## 本次范围

只修改 Windows 启动、服务管理和对应测试及使用说明。手机客户端和 IPA 不需要重新构建。软件源发布凭据与手机网关凭据属于不同用途，不能混用。

当前仅完成设计及只读检查，尚未修改运行中的服务、启动项或环境变量。
