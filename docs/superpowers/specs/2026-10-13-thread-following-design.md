# 会话关注设计

## 已确认的需求

运行中的会话不再自动置顶。原会话置顶改为“关注”；关注会话始终在顶部关注区显示，并从项目内移出，取消关注立即回到项目。关注会话的成功回合完成时，无论由电脑还是手机发起，都通知订阅手机。

## 兼容与列表

继续复用本地按设备保存的置顶 ID 集合作为关注集合，已有置顶自动成为关注，无需用户重新选择。所有用户可见菜单、分组、成功与失败提示均改为关注。仅关注会话进入顶部，运行中与未读会话保留状态标记，在最近/项目内正常显示。关注会话不会同时出现在项目内；搜索依然包含关注会话。取消关注后按原项目与活动时间重新显示。

## 通知规则

本地关注集合按设备同步到现有 Bark 手机订阅；各手机独立维护关注。关注会话的实时 final answer 与成功 turn/completed 都到达后才发送一次完成通知，不限制移动端来源；失败、打断、历史同步、子 Agent 与内部会话沿用现有静默策略。取消关注停止后续电脑发起回合的通知，不补发历史。

未关注的会话继续保留现有移动端发起完成通知与需要回答通知。系统通知也允许关注会话的电脑发起完成事件；其前后台和当前打开会话规则保持原状。App 退出后的通知沿用 Bark 通道，网关保存订阅执行副本，并独立持续观察关注会话；网关重启后恢复关注观察。电脑进程的回合需通过现有可读历史/运行状态核对，不能依赖只为手机正在运行回合保留的连接。启动观察先建立历史基线，只通知观察后完成的新回合，避免关注旧会话立即补发旧通知。订阅更新立即同步，离线/失败时复用重试与失败设备提示。

## 实现方案

推荐扩展现有本地集合与通知订阅，避免丢失原置顶。另建关注存储会要求一次性迁移且增加两套状态，不采用。

完成追踪保留移动来源授权信息，同时允许被关注回合产生完成事件；投递按每个订阅判断“移动发起或该订阅关注”。同一 Bark 地址多个订阅合并发送一次，不能向未关注且未移动发起的其他手机发送。旧订阅缺少关注字段视为空。

## 验证与交付

TDD 覆盖关注/取消、顶部唯一展示、运行中不自动提升、未读标记、旧置顶恢复、按设备同步、HTTP/流式电脑发起完成、多手机隔离、重复与重启去重、取消关注、失败/历史静默。执行相关 UI/通知/网关测试、typecheck、发布契约与适配器恢复回归，中文 Conventional Commit 推送固定 SHA。客户端与网关分别 ready 同一 SHA，等待双方成功凭证及 APK/签名 IPA/OTA/unsigned 软件源验收。
