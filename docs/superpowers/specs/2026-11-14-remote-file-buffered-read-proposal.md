## 第47项已确认A

**把 `RemoteFiles.read` 固定改为短命令的有界缓冲窗口。** 一个窗口一个固定Python进程，自然退出后取完整buffered结果；不再让该读取依赖长进程连续outputDelta。上传、提交收据、查询和清理继续现有已审查协议；不自动在两种读取方式间回退。

- 同一个ready session、完整账号/目标绑定、默认权限与原始目标路径语义继续生效；路径只作为JSON数据交给目标，不使用网关同路径文件，不增加物理连接或远端常驻agent。
- 保持512KiB块、4块窗口、最多4个文件操作、每文件16MiB及全局64MiB逻辑预留；每个文件最多一个活动读取进程。官方exec对stdout/stderr分别设置3MiB捕获上限；文件协议额外限制stdout不超过3MiB，stderr只接受固定短证明，完整RPC仍受现有8MiB入站及1MiB出站限制。内存采样不能替代对实际持有缓冲和预留释放的验证，也不把64MiB解释为整个OS进程RSS上限。
- 原第47项为默认20秒、最高180秒。2026-11-14用户选择第49项A后，仅read显式最高期限改为600秒（已实现并本地验证，首轮SPEC发现发送期限缺口，修复已本地验证、待新SHA复审，QUALITY/官方未开始），默认仍20秒，单窗口watchdog/RPC及其他文件操作最高180秒。单操作绝对期限覆盖准备、全部窗口、消费暂停、最终校验和结束；不按窗口或进度重置，不自动延长已申请预算。当前100MiB单次样本不构成任意网络条件下必然成功的吞吐承诺。
- 每窗口打开原路径，读取前后同时检查FD与当前路径的dev/ino/mode/size/mtime/ctime，全部窗口绑定同一原版本。严格检查nonce、字段集合、窗口范围、顺序、规范base64、长度与逐块SHA；不把退出码0当完整输出证明。
