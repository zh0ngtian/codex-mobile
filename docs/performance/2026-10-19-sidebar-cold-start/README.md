# 冷启动边栏会话列表耗时分布

测量时间：2026-10-19 11:03:00—11:08:41（Asia/Shanghai，末次为启动时间）。

- iPhone 17 Pro / iOS 27.0 / 正常字号 / 竖屏；现有 0.3.8（3008）Debug 安装包，原生界面，单设备范围。读取现有1个真实网关的13个项目及“无项目”分组。
- 正式采样30次，每次终止App进程后重新启动，保留App数据、HTTP会话及服务端/磁盘缓存。另有2次校准，核对探针和界面后调整采集方式，未混入正式统计。
- 起点为调用simctl launch前的宿主机时间；相对Web时钟使用performance.timeOrigin + performance.now()对齐。启动调用本身的开销保留在启动口径中，未作为纯iOS系统启动指标。
- “首批新会话”要求真实的关注/运行/未读摘要返回后，有包含会话行的新快照提交原生桥；“全部分组”要求列表加载器onSettled执行，并提交随后快照。终点到原生桥派发为止，尚未包含Swift解码、SwiftUI布局及屏幕实际显示。
- “全部分组”覆盖各分组的初始分页及补取，不表示将每个项目的所有历史会话加载完。折叠状态保持现有设置，折叠项目仍参与后台加载。

## 请求形态与主要等待

- 30次均完成14个分组，每轮项目加载回调合计57条会话记录。每轮21次thread/list、47次thread/read及1次thread/loaded/list，网络及RPC错误均为0，项目错误均为0。
- account/rateLimits/read的fetch至JSON解析完成耗时为1074—2720ms，中位数1477ms。首个thread/loaded/list均在它完成后0—29ms发出。当前调度器在前台请求仍占用时等待后台队列，与这段时间顺序一致；该观察不用于区分网络、网关和上游CPU。
- 每轮无项目分组读取7页全局thread/list，共扫描327条记录；其余14次带cwd的分页用于13个项目（其中一个项目补取一页）。无项目记录按ID从全局页筛选，未收集足够记录时会继续扫描至末页。
- 最长的连续阶段是关注/运行/未读摘要完成后的项目分页补齐。两项可继续定位的候选为额度读取占用前台期间的列表等待，以及无项目分组的全局扫描。本轮仅测量，没有实施优化。

## 复核、产物和适用范围

- [逐次样本](samples.csv)、[统计结果](summary.json)、[脱敏事件](trials.json)、[环境及原包散列](environment.json)、[完整性及环境恢复复核](validation.json)。事件仅含阶段、耗时、请求方法、数量及本次采样内的匿名项目序号，不保存会话ID、标题、正文、设备地址或口令。
- 在已有安装包的临时副本中注入轻量JS探针，原生可执行文件与原包一致；没有重新构建Web、APK或IPA。正式采样期间没有进行界面树或截图轮询。采集在列表完成后延迟400ms发送到本机回环收集器，该延迟不计入指标。
- 校准后才开始这30次固定采样，没有按性能结果剔除样本。正式样本全部包含1次加载开始、1次完成、14个项目回调及最终快照；完整事件和CSV均可复算。
- 测试后恢复原始安装包，核对HTML、JS及原生可执行文件散列，释放模拟器锁并关闭收集器；未发送消息或创建测试会话。
- 适用于当前配置下的日常杀进程重开。Debug、模拟器、本机网关和缓存状态会影响绝对数值，30个样本的P95仍有较大不确定性；真机Release的可见首帧需要另行测量。
