## 20次首次展开的数据分布

每次终止进程后启动，全部已知分组默认折叠；等待目录/摘要结束、侧栏展开稳定，再实际点击原生「展开项目 codex-mobile」按钮。当前项目在本次进程中尚未加载首批；真实网关和上游保持运行，不清除系统缓存或摘要索引。这不是网关首次建索引、点击时目录尚未就绪或真机网络场景。

| 计时区间 | P50 | P95 | 最小 | 最大 |
| --- | ---: | ---: | ---: | ---: |
| Web收到原生展开命令→首个本组五条且ready的原生投影 | 91毫秒 | 113毫秒 | 77毫秒 | 120毫秒 |
| 本组 `thread/list` 请求派发→响应JSON解析观察点 | 52毫秒 | 73毫秒 | 38毫秒 | 81毫秒 |
| 独立网关向真实上游转发本组请求→收到上游响应 | 39毫秒 | 64毫秒 | 31毫秒 | 71毫秒 |

每轮点击前项目列表请求为0；点击后均只请求当前组一次、`limit:5`，投影五条含运行会话。点击后无 `thread/read`、无项目请求错误或运行异常，20次均保留，没有截尾。第4、5轮各有一次点击前初始化请求被取消，随后初始化成功、目录及摘要就绪；这两轮仍在统计内，不冒称全程没有任何取消。

起点由原生按钮通过既有桥接发出的真实 `project.toggle` 命令触发，观测发生在Web事件入口，**不包含触摸事件到Web接收的桥接时间**。终点采用收到命令后第一次满足条件的投影，不能用稍后重复投影或辅助功能树里存在的隐藏行代替。RPC解析观察点来自响应副本，与App消费响应并行；三个区间相互重叠，不相加。

## 3次原生画面抽验

另做3轮进程冷启动后真实按钮展开，录制模拟器原生界面。使用同一视频内部PTS，起点为项目文件夹图标首次从折叠状态改变的帧，避免把工具调用耗时或录像开始时间当作点击时间。终点为五行标题各自达到最终文字墨色对比度90%，连续保持五帧，并人工核对画面确实为本组五条。25%对比度另列为文字开始显现的观察点，不称为清晰显示。

| 轮次 | 展开首次画面变化→五条开始显现 | →五条接近最终清晰度 |
| --- | ---: | ---: |
| 1 | 412毫秒 | 512毫秒 |
| 2 | 398毫秒 | 513毫秒 |
| 3 | 408毫秒 | 525毫秒 |

因此本次画面抽验可表述为**展开动画开始后约0.51–0.53秒清楚显示五条**。起点已经是首次可见变化，不是精确触摸时刻；起点相邻帧间隔12–37毫秒，终点相邻帧间隔2–20毫秒，不提供虚假的毫秒级触摸到上屏精度，也不将3轮当作20轮画面P95。录像组的数据就绪分别为99、93、96毫秒，与不录像的20轮独立记录。

原生 `ProjectRow` 当前先拉开高度，再渐显文字；代码分别使用0.25秒高度动画和0.18秒渐显，数据由加载态切换时高度也会更新。视频显示数据已就绪后文字仍等待动画，余下可见延迟主要在呈现阶段。若继续缩短视觉等待，可以调整这一顺序；本轮仅测量，没有擅自改动已约定的展开动画。
