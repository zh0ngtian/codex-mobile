# 表格布局与用户消息长按菜单修复

- 开发基线：`c116165a12931f691ec8dd677c21ae4412cfb6c7`（main）。
- 范围：原生 Markdown 表格及 AgentUI 用户消息菜单；按默认流程只交付源码，不发包、不部署。
- 复现来源：用户指定会话 `01a157b1-c0db-7762-a920-f11eacd08492` 的“部分／迁移内容”表格。只读会话，提取表格进入 DEBUG 离线夹具，不修改、发送或归档该用户会话。

## 原因与实现

表格仅限制最大列宽，Grid 探测宽度与 UIKit 文本最终布局宽度不一致，长列被压成逐字窄列，并越过行边界。现在按渲染后的文字、表头字重和系统字体环境计算各列最大自然宽度，单列仍最多260pt；先固定同列宽度，再计算实际换行高度。保留原横线、字体、链接、图片及 HTML 文档范围。

用户消息菜单原来仅挂在气泡背景上，正文的系统选文先处理长按。现在菜单覆盖整个气泡，按“复制、编辑、选择文本”排序；默认正文不直接进入选文。`NativeMessageContextMenu` 使用 UIContextMenuInteraction 的系统关闭动画完成回调交接操作，避免旧菜单清理选区时撤销新选文。选择文本后请求 UITextView 的系统选择手柄，并通过 UIEditMenuInteraction 呈现系统菜单，保留复制及既有引用动作。内容保留 AppSession、偏好与显示环境，辅助功能节点仍由正文自己管理。结束选择后恢复气泡菜单；不可编辑时禁用编辑，仅附件消息禁用选文。
