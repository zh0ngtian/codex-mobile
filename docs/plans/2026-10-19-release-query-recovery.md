# 发布查询故障恢复计划

用户已批准将查询未知与确认失败分开：网络故障保留原批次、冻结 SHA、版本和 CI run ID，恢复后只完成缺失步骤。配套通用协调器升级至 0.1.7，实施与故障验收主计划在 release-coordinator 仓库 `docs/superpowers/plans/2026-10-19-network-query-recovery.md`。

- [ ] 先运行现有发布 Python 回归，建立干净基线。
- [ ] 用 RED 用例复现 GitHub 重试耗尽后被当作永久失败，以及只读下载断线。
- [ ] 引入明确的只读暂时故障类型，入口输出 `done:false` 与 `retryable:{kind:"transient-read",reason:脱敏原因}`；永久错误仍失败，POST 不盲目重试。
- [ ] 保留 CI run/attempt、部分下载与完整校验；重启/恢复不重新分配版本或重建。
- [ ] 与新版核心进行故障注入，核对同一批次/SHA/版本/run 和单次构建；覆盖响应丢失、重复查询、真实失败与来源散列错误。
- [ ] 独立规格/质量审查，运行完整发布回归并提交推送 main。
- [ ] 更新协调说明和验收记录，核对本机新核心运行状态。

范围仅为发布适配脚本、测试和文档，不涉及客户端/网关运行源码；不登记客户端发包批次、不构建或发布 APK/IPA、不部署网关、不创建新业务测试会话。既有失败批次及发布历史保持不可变。实现遵循 TDD，原服务升级前备份并等待活动批次结束。
